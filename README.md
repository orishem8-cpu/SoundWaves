# SoundWave MVP

Русскоязычный MVP SaaS-платформы для продвижения музыкальных релизов. Интерфейс работает в **демо-режиме без внешних сервисов**. Интеграции Supabase, платежей и Telegram подготовлены как безопасные серверные точки подключения, но не активируются автоматически.

## Требования
- Node.js 20.9+ (рекомендуется Node.js 22 LTS)
- npm

## Запуск локально
1. Распакуйте архив и откройте папку `SoundWave` в VS Code.
2. Скопируйте `.env.example` в `.env.local` (можно оставить пустые значения).
3. В терминале выполните:
   ```bash
   npm install
   npm run dev
   ```
4. Откройте http://localhost:3000

## Демо-доступ
- Клиент: нажмите «Демо-аккаунт» на странице входа.
- Администратор: нажмите «Демо-администратор» на странице входа.
- Демо-режим использует браузерное состояние и демонстрационные данные. Он **не является настоящей авторизацией**, не предназначен для production и не предоставляет реальную оплату/публикацию.

## Возможности MVP
- Лендинг: описание сервиса, процесс, тарифы, FAQ.
- Демо-вход клиента и администратора.
- Клиентский кабинет: обзор, публикации с фильтрацией, материалы (загрузка/удаление в текущей сессии), платежи, поддержка, настройки.
- Админ-панель: клиенты, поиск, календарный список публикаций, создание публикации, изменение статуса, статистика.
- Адаптивный тёмный UI с градиентным акцентом.
- SQL-миграция Supabase: схема, индексы, триггеры updated_at, RLS и Storage bucket policies.

## Настройка Supabase
1. Создайте проект Supabase.
2. Выполните `supabase/migrations/202610310001_initial_schema.sql` в SQL Editor.
3. В Authentication → URL Configuration настройте локальный и production URL.
4. В Storage создайте bucket `materials` (или примените инструкции миграции).
5. Укажите `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` в `.env.local`.
6. Для переключения auth-клиента установите `NEXT_PUBLIC_USE_SUPABASE_AUTH=true`.

В текущем MVP экраны продолжают демонстрировать seeded data; для production требуется связать серверные actions/API с таблицами Supabase и убрать демо-вход. Не выставляйте service role key в `NEXT_PUBLIC_*` и никогда не отправляйте его в браузер.

## Платежи
- ЮKassa: настройте магазин, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, создавайте платежи только на сервере и проверяйте webhook подпись/статус.
- Stripe: настройте `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, используйте серверные Checkout Sessions и проверку webhook.
- На данный момент кнопки тарифов/продления работают как демонстрационные UI-действия; реальное списание не производится.

## Telegram
Создайте бота через BotFather, добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Реальная отправка сообщений требует серверного API route и проверки пользовательского ввода. В MVP есть ссылка на Telegram и demo-форма поддержки.

## Деплой на Vercel
Импортируйте репозиторий GitHub в Vercel, добавьте переменные окружения, запустите deployment. Проверьте Supabase Auth redirect URLs и домен.

## Ограничения и безопасность
- Демо-auth — только для локального ознакомления.
- Не используйте демо-данные как реальные клиентские данные.
- Тикеты и материалы пока хранятся в браузерном состоянии, а не в облаке.
- TikTok/социальные площадки: ссылки добавляются вручную; доступ к API не предполагается.
